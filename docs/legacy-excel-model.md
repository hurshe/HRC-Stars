# Разбор текущей таблицы Excel/Sheets

Источник: скриншот листа `SERVER TEST SCORES` (2026-08-23). Это фактическое ТЗ на модуль «Матрица обучения» — система должна заменить эту таблицу.

## Листы книги

`PINY` · `TRAINING CALENDAR 2024` · `TRAINING MIT CALENDAR` · `BHP.` · `TRAINING DEPARTMENT` · `SOHR` · `Ilu trenerów` · `FSS level 2` · `Trainer Ratio & Documentation` · `ROCZNICE STAFF` · `Arkusz23` · `BARTENDER TEST SCORE` · `SERVER TEST SCORES`

Вывод: **тесты разбиты по позициям** (Server / Bartender — отдельные листы с разными наборами тестов). Плюс есть календари обучения, реестр тренеров, годовщины сотрудников, пины.

## Структура листа с результатами тестов

### Блок «кто»
| Колонка | Содержание |
|---|---|
| `NAME – SERVER` | ФИО сотрудника, фон = статус (зелёный / голубой / жёлтый) |
| дата | дата старта обучения / найма (`10.05.21`, `15.05.2023`, `maj 24`) — формат непостоянный |

### Блок «тесты» — повторяющаяся пара колонок
Для каждого теста идёт **две колонки: сырой балл и процент**, плюс перед ним колонка со способом сдачи (`ONLINE` / пусто = бумага).

| Тест | Наблюдаемый максимум |
|---|---|
| `BI` → `NHO Score` | 15 |
| `FSS 1` → `FSS 1 SCORE` | 10 |
| `H & S` → `H & S SCORE` | 10 |
| `BRAND` → `BRAND SCORE` | 27 |
| `ALLERGENS` → `ALLERGEN SCORE` | 20 |
| `UNITY` → `UNITY SCORE` | 24–25 |
| `BEVERAGE TEST` → `BEVERAGE TEST SCORE` | 31 … 47 (менялся) |
| `FOOD TEST` → `FOOD TEST SCORE` | 56 … 119 (менялся) |

**Важная находка:** максимальный балл по BEVERAGE и FOOD менялся со временем — `31 = 100 %`, но `45 = 96 %`, `113 = 95 %`, а `56 = 80 %`. То есть тесты редактировались, а старые проценты остались от прежних версий. В системе это лечится **версионированием тестов**: у каждой попытки хранится ссылка на версию теста с её максимумом, процент считается автоматически и никогда не расходится.

### Цветовая легенда (шапка листа)
| Цвет | Значение |
|---|---|
| голубой | 0–10 % |
| розовый | NOT PASSED |
| жёлтый | 60–70 % |
| светло-оранжевый | NOT PASSED |
| зелёный | 80–100 % |
| светло-зелёный | PASSED |

Пороги пересекаются и заданы вручную — в системе порог задаётся в настройках теста, цвет вычисляется.

### Блок «документы сотрудника»
`CV` · `Interview I i II` · `Job Description` · `Learning Technology Policy` · `BSP Visual Validation` · `BSP Last Page` · `Employee Handbook` · `Orientation Sign Off Sheet` · `Serwer Evaluation` · `REX form` · `Station Pin`

Легенда статусов (вторая шапка): **Paper** (белый) · **Drop BOX** (зелёный) · **Incoming** (жёлтый). Плюс серый = не требуется / неприменимо.

То есть по каждому документу отслеживается **где он физически лежит**, а не только «есть/нет». В системе это заменяется реальным файлом + статусом, но статус «ждём подписанный оригинал» сохранить нужно.

Отдельные колонки содержат **даты, а не галочки**:
- `Orientation Sign Off Sheet` → дата подписания
- `Serwer Evaluation` → `07.01.22 next: 06.23` — **периодическая переаттестация со сроком следующей**
- `REX form` → дата
- `Station Pin` → `YES`

## Что из этого следует для системы

1. **Позиция сотрудника — отдельная сущность.** У каждой позиции (Server, Bartender, …) свой набор обязательных тестов и свой набор обязательных документов. Один человек может занимать несколько позиций.
2. **Тесты версионируются.** Процент считается от максимума той версии, которую человек проходил.
3. **Документы сотрудника — это чек-лист требований по позиции**, а не свободная папка. Требование → статус → файл → дата → срок действия.
4. **Есть периодические аттестации** с датой «следующая» — нужны напоминания.
5. **Главный экран менеджера — та же матрица**, но живая: строки = сотрудники, колонки = тесты и документы, цвет считается системой.
6. **Пины и годовщины** (`PINY`, `ROCZNICE STAFF`) — отдельный слой признания, логично связать с модулем Wild Cards.
